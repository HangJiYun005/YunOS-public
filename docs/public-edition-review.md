# YunOS 公开版：功能取舍与资料导入改造评估

状态：源码评估与实施方案，尚未执行功能删除或完成新导入程序。
评估日期：2026-11-15。源码基线：810f7f3。

## 1. 产品目标

YunOS 是保存在自己电脑上的个人文字资料库。用户可以保存微信中复制的重要消息、随手记录、文章摘录、工作材料以及各种对话记录，再通过搜索找到原文。

公开版不以 AI 对话为中心，不包含鲸鱼人格、鲸鱼专属分区或私人主机约定。AI 聊天导出只是可选数据来源之一。“任何文字信息”是内容范围；首版并不承诺识别所有文件格式或自动读取所有软件。

首版闭环：打开软件 → 粘贴文字或选择文件 → 预览 → 保存 → 搜索 → 阅读 → 导出/备份。

## 2. 当前源码的实际问题

| 发现 | 代码位置 | 对用户的影响 |
| --- | --- | --- |
| 默认记忆域为 whale | memory/read_only_retriever.py 的 DEFAULT_MEMORY_SPACE、retrieve | 普通导入记录会被默认检索范围排除 |
| 首页显式请求 whale | web/app.js 的首页搜索请求；tools/local_web.py 的 parse_memory_space | 隐藏下拉框不能解决搜索遗漏 |
| 已存在跨记忆域查询 | memory/read_only_retriever.py 的 search_all_memory_conversations；/api/search 的 scope=all、aggregate=conversation 分支 | 可以复用查询思路，但结果仍以对话为单位 |
| 页面同时装载资料和代理功能 | web/app.js 的 SIDEBAR_NAVIGATION；tools/local_web.py 的模块导入和路由 | 简单资料管理被目标、委托、画像、运行和授权功能包围 |
| 导入是命令行操作 | tools/chatgpt_export_importer.py 的 main | 用户要处理导出包路径、数据库和启动参数 |
| 同目录导入删除旧目标库后重建 | tools/chatgpt_export_importer.py 的 build_outputs | 不能直接包装成日常“添加资料”按钮 |
| 增量导入仍面向聊天模式 | tools/chatgpt_incremental_import.py 的 CONVERSATION_COLUMNS、MESSAGE_COLUMNS | 不能直接用于任意文字文档 |
| 现有规范化导入可借鉴 | memory/ingestion_core.py、ingestion_adapters/chatgpt.py、ingestion_ledger.py | 有校验、来源和批次机制，但不能把整套生产授权流程塞给普通用户 |
| 桌面启动读取私人主机配置 | desktop/host.cjs、scripts/start_yunos_primary_host.ps1 | 新用户没有配置和五库便无法启动 |
| 安装包记录构建机器源码位置 | desktop/package.cjs 的 host-location.json | 不是可直接交给另一台电脑使用的独立软件包 |

静态检查：web/app.js 约 12,860 行，tools/local_web.py 约 4,050 行；后者在 AST 中直接引用 26 个不同的 memory 模块。whale 字样分布在 memory 的 4 个、tools 的 13 个、tests 的 52 个、web 的 6 个源码文件中。这些是依赖排查线索，不是可以直接删除的文件数量。

## 3. 取舍清单

| 模块 | 决定 | 实施方式 |
| --- | --- | --- |
| 本地保存、关键词搜索、原文阅读 | 保留并作为核心 | 单一资料库，默认搜索全部资料 |
| 来源、原始时间、保存时间 | 保留 | 缺失的来源时间留空，不用导入时间冒充 |
| 标签、收藏、用户分类 | 保留并简化 | 不预置私人项目；先保持默认列表可用 |
| 时间线 | 保留为排序/筛选能力 | 首版不必单独做复杂页面 |
| 粘贴文字、TXT/Markdown 导入 | 首轮新增 | 统一进入预览和保存流程 |
| ChatGPT 导出导入 | 可选保留 | 在“其他格式”中识别；不再占据首页定位 |
| 微信内容 | 首轮支持复制粘贴、已有纯文本文件 | 来源可选“微信”；不自动猜测联系人、发言者或聊天时间 |
| 鲸鱼分区、通用/鲸鱼切换、人格 | 从公开产品移除 | 同步处理查询、界面、API、配置和相关测试；不是改名 |
| 鲸鱼提示词预览和上下文专属工具 | 从公开基础版移除 | whale_chat.py、tools/preview_whale_prompt.py 等在依赖拆分后退出发行清单 |
| 个人画像、记忆自动总结和修订流程 | 退出基础版 | 保留历史代码供未来提取，不在主程序装载 |
| AI 问答、语义搜索 | 暂缓为可选扩展 | 不阻塞无网络、无 Key 的基本使用 |
| 目标、计划、代理执行、委托、授权控制台 | 退出基础版 | cognitive_*、operational_state_*、runtime_* 相关产品入口和路由不随基础版发布 |
| 原文来源追踪 | 保留 | 不把它和复杂证据图谱绑定 |
| 知识图谱、自动学习、复杂证据预算 | 暂缓 | 不进入首版主界面和运行依赖 |
| 桌面程序与导入小程序 | 保留方向，改造 | 同一安装包、同一数据服务、两个入口 |
| 手机离线缓存、远程访问、跨机同步 | 暂缓 | 首版以单机桌面为验收边界，不继承旧浏览器缓存的隔离假设 |
| 私人验收、生产迁移与封板文档 | 退出用户导航 | 新版说明只描述实际可用功能，历史材料不当安装前提 |

删除代理模块时保留有价值的基础措施：参数化 SQL、事务、输入大小限制、路径检查、失败回滚和来源记录。功能简化不等于移除这些基础保障。

## 4. 导入小程序：同一软件的轻量入口

建议交付两个快捷方式：“YunOS”和“YunOS 资料导入”。二者启动同一应用，后者带 --import 参数，直接打开小窗口。不另造一套数据库或独立 Python 安装流程，也不要求主界面已经打开。

### 粘贴文字

打开导入窗口 → 用户自行粘贴 → 可选补充标题和来源 → 保存。

正文必填；标题默认使用第一行的简短片段，允许修改；来源默认“手动记录”，可选微信、网页、文档、其他。分类和标签都可跳过。剪贴板只在用户粘贴时使用，不后台监视或自动收集。

### 文件导入

选择文件或拖入文件 → 显示每个文件的预览和结果 → 点击“导入” → 显示成功、重复、失败的数量。

首轮支持 .txt 和 .md；支持多选。UTF-8、带 BOM 的文本先自动识别；其他编码提供预览和明确的编码选择，不以乱码静默入库。每个文件默认保存为一份资料，Markdown 首轮以安全纯文本阅读，不执行 HTML 或脚本。

遇到无法识别的文件，说明原因和可用替代方式。DOCX、可提取文字的 PDF、结构化聊天 ZIP 属于后续适配器；扫描件 OCR、图片/语音识别不在首轮范围内。

### 导入反馈

- 保存成功后提供“查看资料”和“继续导入”。
- 同一内容重复选择时，默认跳过并给出提示；不同来源的相同正文保留来源关联。
- 同名但内容不同不能覆盖旧资料；作为新资料或明确的新版本处理。
- 导入过程可取消；已完成的文件保持成功，当前未完成文件回滚。
- 批次结果说明哪些文件成功，哪些未成功；重试不重复写入已完成内容。
- 主程序未运行时，导入入口能初始化自己的资料库并完成保存。

桌面同进程写入先采用单实例串行队列，避免主界面与导入窗口争抢写入。文件路径由主进程文件选择器接收，通过受限 IPC 调用导入；不向网页开放任意路径读写。

## 5. 资料模型和首次启动

公开基础版采用独立的用户数据目录，例如 Electron 的 userData 下保存 library.sqlite。第一次启动自动建库，无需复制五库、填写主机名或选择源码路径。

建议的最小模型：

- documents：标题、正文、内容类型、内容摘要哈希、创建/更新时间。
- sources：来源名称、原文件名、原始时间（可为空）、与资料的关联。
- imports：导入批次、文件状态、错误原因、重复识别结果。
- tags/document_tags：用户标签。
- SQLite 全文索引：可重建，不是唯一原文存储；中文搜索需专门验收分词/子串策略。

聊天可作为一种资料类型保留顺序和发言者信息；普通文字不需要虚构 conversation_id、角色或模型名称。初期可先保存格式化原文，后续再做结构化聊天阅读。

数据库放在软件更新不会覆盖的位置。基础版写入在本机受控入口完成；不能继续把所有操作设置成只读，否则“保存资料”无法成立。远程访问暂不启用。

旧库迁移是独立功能：只读扫描旧库 → 预览数量 → 复制到新库 → 校验数量和正文。旧 whale/general 字段只用于兼容识别，不能继续决定新产品的可见性。原数据库不改写、不删除；迁移中断可重试。

## 6. 推荐改造顺序和验收

### 第一步：建好公开版核心

建立独立基础版入口、自动初始化资料库、通用资料模型、保存和搜索服务。先以合成数据验收，不直接改私人运行库。

通过条件：没有任何旧数据库、没有私人配置、没有 API Key，仍可首次启动；保存一段普通文字后立即搜到，重启后仍存在；微信来源文字与普通文字均默认可见。

### 第二步：交付导入窗口

做粘贴、文件多选/拖入、预览、重复提示、结果反馈。主窗口和导入窗口复用存储服务。

通过条件：UTF-8 中文、带 BOM 文本、常见中文编码、空文件、同名不同内容、重复文件、失败取消均有明确结果；导入中断不损坏已有资料；导入入口单独启动可用。

### 第三步：清理公开版产品界面和依赖

主导航收敛到资料、导入、标签/分类、设置；去掉 AI 模式切换、鲸鱼分区、画像、运行、目标、委托等基础版不使用的入口与接口。先拆依赖再移除旧实现，避免启动时仍加载被删除模块。

通过条件：默认检索覆盖全部资料；无 whale 必填参数，无人格文件依赖，无未配置高级功能占位页；桌面入口与搜索服务不装载旧代理模块。原有私人系统另行保留，不要求继续满足公开版的新界面断言。

### 第四步：可分发的软件包

构建时带上所需运行时与核心代码，移除 host-location.json 对构建机路径的依赖。首版可选择便携 ZIP，后续再做安装器；两个入口均随包交付。

通过条件：在未安装 Python/Node、没有原源码目录的新 Windows 环境中，解压或安装后可以启动、导入和搜索。换一个解压路径仍能工作。实际完成前不标注“免配置可用”。

### 第五步：旧库迁移和更多格式

验证旧库只读迁移，再按需求增加聊天 ZIP、DOCX 和 PDF 文字提取。外部 AI、微信自动读取和跨机同步各自评估，不捆绑进基础安装。

## 7. 本轮边界

本轮交付是基于源码的取舍清单、导入窗口规格和实施验收条件。没有删除现有功能、迁移数据库或生成新软件包。现有 README 和安装教程描述的仍是旧源码实际能力；待新入口可运行后再一起替换，避免把规划写成已实现。

后续实施按此顺序推进即可，无需为了每个可逆的常规代码调整重复确认。产品方向如有变化，再调整这份清单。
