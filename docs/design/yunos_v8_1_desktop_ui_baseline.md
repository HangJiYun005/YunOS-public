> 文档状态：**权威设计基线**  
> 适用版本：YunOS v8.1 Desktop  
> 创建日期：2026-07-18  
> 适用对象：Codex 实现窗口、代码评审、独立验收、后续维护者

## 0. 文档权威性

本文件是 YunOS v8.1 桌面端前端实现的统一产品合同。

所有 v8.1 子任务在开始编码前必须先读取本文件。实现可以在不改变产品意图的前提下微调数值，但不得擅自改变已锁定的产品结构、交互方向和视觉原则。

若代码、旧页面、旧文档或模型自行生成的界面与本文件冲突，以本文件为准。

## 1. 产品定位

YunOS 不是聊天机器人网站，不是 ChatGPT 换皮，不是传统后台管理系统，也不是大型卡片式仪表盘。

YunOS 的定位是：

> 模型无关的个人 AI 记忆与上下文系统。  
> 系统负责记忆工程，LLM 负责理解和表达。

桌面首页应被理解为一个安静的个人记忆操作界面，而不是“开始聊天”的页面。

核心体验应回答四个问题：

1. 我拥有哪些历史记忆与证据？
2. 我现在想查找什么？
3. 我希望 YunOS 基于哪些记忆进行分析？
4. 这个结果来自哪里，执行过程是否可信？

## 2. v8.1 范围

v8.1 只负责桌面端前端重构与现有能力的产品化呈现。

### 2.1 本版本包含

- 桌面端应用外壳
- 空白首页
- 中央 Omnibox
- “记忆搜索 / AI”显式模式切换
- 记忆搜索轻量结果
- AI 文档式结果页面
- 可隐藏侧栏
- 宽屏桌面与紧凑桌面两档适配

- 生产数据库结构调整
- 新的记忆算法
- 全局深色主题
- 复杂工作台或可视化仪表盘

## 3. 设计原则

### 3.1 大道至简

默认页面只显示完成当前动作所需的最少元素。

首页不主动占据用户注意力。用户开始输入后，功能再逐层出现。

### 3.2 不以聊天为中心

YunOS 的核心对象不是“聊天消息”，而是：

- 记忆
- 证据
- 来源
- 画像
- 上下文
- 执行结果
- 审计记录

AI 结果应表现为一份基于个人记忆生成的结构化结果，而不是“用户一句、助手一句”的对话气泡。

### 3.3 显式模式优先

v8.1 不做自动意图判断。

用户通过 Omnibox 右侧控件明确选择：

- 记忆搜索
- AI

系统记住上一次选择。

只有当未来真实测试证明自动路由准确、稳定、可解释，并达到约 90% 以上的可接受准确率后，才考虑加入“自动模式”、放入二级菜单或隐藏手动切换。

### 3.4 大屏增加空间，不放大控件

大屏应提供更多留白、内容宽度和多栏能力，而不是把输入框、侧栏、字体和按钮等比例放大。

### 3.5 透明但不喧闹

来源、证据、不确定性和执行详情必须可访问，但默认不应抢占主要视觉层级。

## 4. 信息状态分类

### 4.1 已锁定

Codex 不得改变：

- 首页大面积留白
- 首页无问候语、标题和引导文案
- 中央单一胶囊 Omnibox
- Omnibox 两端为完整半圆
- 模式切换位于 Omnibox 右侧
- 模式为“记忆搜索 / AI”
- 记住上一次模式
- 不加入自动意图识别
- 记忆搜索结果从 Omnibox 下方轻量展开
- AI 提交后进入文档式结果页面
- 不使用聊天气泡
- 侧栏默认隐藏
- 首页侧栏覆盖弹出
- 工作状态侧栏推动主内容
- 默认浅色
- AI 状态只使用局部冷蓝反馈
- 不做全局深色或 VS Code 风格
- 桌面端优先，移动端以后单独设计

### 4.2 允许实现时微调

Codex 可在浏览器实测后微调，但必须说明理由：

- 阴影强度
- 边框透明度
- 字号的 1–2px 调整
- Omnibox 的精确宽度
- 侧栏的精确宽度
- 动效时长
- 左侧悬停触发区宽度
- hover 展开和收回延迟
- AI 结果正文最大宽度
- 搜索结果行高与摘要长度

### 4.3 暂未确定

不得擅自永久定型：

- 左侧栏最终栏目名称
- 左侧栏最终排序
- YunOS Logo 的最终图形
- 首次使用时默认进入“记忆搜索”还是“AI”
- AI 结果页各区块默认展开或折叠
- 是否在未来加入自动模式
- 手机端导航结构
- 深色主题是否在未来提供

暂未确定项应使用可替换、低耦合实现。

## 5. 桌面设备基线

### 5.1 Wide Desktop

主要基准设备：

- 27 英寸
- 2560 × 1440
- 16:9
- Windows 缩放 100%
- CSS 逻辑视口约 2560 × 1440

特点：

- 横向空间充足
- 允许更大留白
- 控件尺寸保持克制
- 不因屏幕宽而无限拉长

### 5.2 Compact Desktop

主要基准设备：

- 16 英寸
- 2560 × 1600
- 16:10
- Windows 缩放 150%
- CSS 逻辑视口约 1707 × 1067

特点：

- 仍属于完整桌面端
- 主内容和侧栏更紧凑
- 不进入手机布局
- 不压缩到难以点击或阅读

### 5.3 建议断点

```css
@media (width >= 1800px) {
  /* Wide Desktop */
}

@media (1360px <= width < 1800px) {
  /* Compact Desktop */
}

@media (width < 1360px) {
  /* Narrow Desktop，仍不是 Mobile */
}
```

不得仅根据物理分辨率判断布局，必须依据浏览器 CSS 逻辑视口。
相邻布局区间必须连续覆盖分数 CSS 视口，不得通过整数 `max-width` / `min-width` 组合留下媒体查询空档。

## 6. 首页

### 6.1 默认结构

首页只保留：

- 左上角 YunOS Logo 预留位置
- 页面中央 Omnibox
- 左边缘侧栏感应区

其余区域保持空白。

### 6.2 首页禁止内容

首页不得出现：

- “今天想聊点什么”
- “有什么可以帮你”
- 欢迎语
- 产品宣传语
- 快捷任务按钮
- 上传按钮
- 语音按钮
- 蓝色圆点
- 推荐问题
- 最近对话列表
- 最近项目卡片
- 仪表盘
- Runtime 状态大卡片
- 页脚水印
- 大型 YunOS 品牌标题
- 顶部“对话 / 工作台”等标签页

### 6.3 垂直位置

Omnibox 不必机械放在几何中心。

建议位于可用内容区域高度约 44% 的位置，即视觉上略微偏上。

## 7. Omnibox

### 7.1 形态

Omnibox 是首页唯一的核心控件。

要求：

- 单行
- 胶囊形
- 两端完整半圆
- 非普通圆角矩形
- 默认低存在感
- 聚焦后清晰但不过度发光

建议尺寸：

```css
.yunos-omnibox {
  width: clamp(580px, calc(28.604924vw + 131.713951px), 864px);
  height: clamp(52px, calc(1.547479vw + 27.584525px), 67.2px);
  border-radius: 999px;
}
```

建议实际范围：

- Wide Desktop：约 864px
- Compact Desktop：约 620px
- Narrow Desktop：约 580px
- 高度：Wide 约 67.2px，Compact 约 54px，Narrow 约 52px

上述 1359px、1707px、2560px 三个目标设备尺寸继续有效；中间宽度采用连续且封顶的流体缩放。Logo、导航与基础字体遵循同样的有上下限连续原则，不得在单一断点发生剧烈跳变。大屏缩放是有限且封顶的局部调整，不代表整套界面随视口等比例放大。

### 7.2 默认视觉

- 冷白或浅灰背景
- 极淡边框
- 极轻阴影
- 不使用大面积蓝色外发光
- 不使用厚重玻璃拟态
- 不使用纯黑强边框
- 不使用巨大的发送按钮

### 7.3 Placeholder

不使用聊天式问候。

可根据当前模式变化：

- 记忆搜索：`搜索记忆`
- AI：`向 YunOS 提问`

也可以在后续实测中进一步弱化。不得出现“今天想聊什么”。

### 7.4 模式切换

模式切换位于 Omnibox 右侧内部。

模式：

- 记忆搜索
- AI

要求：

- 当前模式始终可辨认
- 不做成页面顶部大标签
- 不做成两个巨大按钮
- 不增加第三个“自动”模式
- 切换结果持久化到本地设置
- 刷新或重新打开后恢复上次模式
- 模式切换不能触发 API 调用

### 7.5 提交行为

- Enter：提交
- Esc：取消焦点或关闭轻量结果层
- 上下方向键：在搜索结果中移动
- Tab：可访问模式切换与提交控件

## 8. 记忆搜索模式

### 8.1 基本原则

记忆搜索是本地、快速、明确的检索能力。

不得调用外部 LLM。

### 8.2 交互形态

用户输入后，结果从 Omnibox 下方轻量展开。

结果层：

- 与 Omnibox 对齐
- 宽度接近或略小于 Omnibox
- 不立即占满屏幕
- 不跳转到大型页面
- 保持 Spotlight 式快速检索感

### 8.3 单条结果建议字段

- 标题
- 匹配摘要
- 时间
- 来源类型
- 会话或消息锚点
- 可选的匹配原因

不得默认堆叠大型卡片。

### 8.4 结果行为

- 点击结果：打开完整会话、消息锚点或记忆详情
- Enter：打开当前高亮结果
- Esc：收起结果
- 无结果：显示克制的空状态
- 错误：显示局部错误提示，不占满页面

### 8.5 性能体验

- 输入后快速反馈
- 可使用防抖
- 不应因搜索导致整页重排
- 不应在每次按键时调用模型
- 不应在默认状态展示调试信息

## 9. AI 模式

### 9.1 基本流程

AI 模式复用 v8.0 已有生产闭环：

```text
用户问题
→ 记忆检索
→ Context Assembly
→ Reviewed Binding
→ LLM 调用
→ Runtime Ledger
→ 来源与审计结果
```

不得在 v8.1 为此新增一套平行执行链。

### 9.2 页面转换

提交后：

1. Omnibox 从首页中央平滑移动到页面上方；
2. 下方出现结果正文区域；
3. 页面进入“任务结果”状态；
4. 侧栏可作为上下文导航；
5. 不显示聊天气泡。

### 9.3 文档式结果结构

AI 结果页建议按以下顺序组织：

1. 结论
2. 分析正文
3. 来源
4. 相关记忆
5. 不确定信息
6. 执行详情

“来源、相关记忆、不确定信息、执行详情”必须可访问，但视觉层级低于结论和正文。

### 9.4 结果页禁止形态

不得使用：

- 用户消息气泡
- 助手消息气泡
- 左右头像
- 连续聊天时间线
- “重新生成回答”作为核心视觉
- 大面积模型品牌标识
- 彩色渐变背景
- 全屏深蓝或黑色科技界面

### 9.5 AI 状态视觉

AI 工作时允许出现局部冷蓝或青色反馈，例如：

- Omnibox 边缘的细微流动
- 很弱的粒子或光点
- 结果区域的局部加载反馈
- 小范围状态高亮

限制：

- 仅限局部
- 仅在 AI 状态出现
- 不覆盖整个页面
- 不造成“国产 AI 官网”式炫光
- 完成后回归安静的浅色界面

### 9.6 截断和失败

需要明确处理：

- 模型响应被截断
- API 失败
- 无检索证据
- 证据不足
- 运行成功但状态检查未读取凭据
- 执行结果与审计详情不一致

错误信息应对用户可读，同时保留进入详细审计页面的入口。

## 10. 侧栏

### 10.1 总体方向

采用“少量全局入口 + 当前上下文”的混合结构。

侧栏不是 ChatGPT 的聊天历史列表，也不是 Notion 页面树，更不是传统后台菜单墙。

### 10.2 首页行为

- 默认完全隐藏
- 鼠标接近左边缘后延迟唤出
- 以 overlay 方式覆盖页面
- Omnibox 不因侧栏出现而移动
- 鼠标离开后延迟收回
- 左上角提供手动展开入口

### 10.3 工作状态行为

进入以下状态后：

- 搜索完整结果页
- 记忆详情页
- AI 结果页
- Runtime 或审计页

侧栏展开时应推动主内容，而不是覆盖关键正文。

### 10.4 建议宽度

```css
.yunos-sidebar {
  width: clamp(208px, 13vw, 240px);
}
```

建议：

- Wide Desktop：232–240px
- Compact Desktop：208–220px
- 导航行高：30–34px
- 图标：约 16px
- 正文：13–14px
- 分组标题：约 12px

### 10.5 内容模型

侧栏采用两层结构：

#### 全局层候选

- 记忆
- 时间轴
- 画像
- 项目
- 运行
- 设置

#### 当前上下文层候选

- 当前任务
- 相关记忆
- 来源
- 最近活动
- 当前项目

以上栏目只是候选，不是最终永久结构。

### 10.6 侧栏禁止内容

- 默认展示几十条历史聊天
- 大型系统状态卡
- 大型图表
- API 余额卡片
- 模型选择器堆叠
- 巨大的用户账户区
- 模仿 ChatGPT 的“新聊天 / GPTs / 项目 / 历史记录”
- 为填满空间而制造无意义栏目

## 11. 视觉规范

### 11.1 默认主题

- 浅色
- 冷白
- 浅灰
- 低饱和
- 大面积留白
- 轻边框
- 轻阴影

### 11.2 字体

优先使用系统 UI 字体，保证中英文清晰。

```css
font-family:
  Inter,
  "SF Pro Display",
  "SF Pro Text",
  "Segoe UI",
  "PingFang SC",
  "Microsoft YaHei",
  system-ui,
  sans-serif;
```

不得为了模仿 Apple 私自分发字体文件。

### 11.3 圆角

- Omnibox：完整胶囊
- 搜索结果行：中小圆角
- 文档结果容器：可使用轻微圆角，但避免大卡片感
- 不得所有元素都使用夸张大圆角

### 11.4 层级

1. Omnibox / 结论
2. 正文
3. 来源与相关记忆
4. 执行详情
5. 系统辅助信息

### 11.5 色彩使用

冷蓝仅作为：

- AI 状态
- 当前选择
- 少量交互反馈

不得作为：

- 全局背景
- 大面积渐变
- 所有按钮的默认颜色
- 侧栏永久主色

## 12. 动效规范

动效目标是解释状态变化，而不是展示技术。

建议时长：

- hover：120–160ms
- Omnibox 聚焦：160–200ms
- 侧栏展开：180–240ms
- 首页到 AI 结果页：220–320ms
- 结果层展开：160–220ms

要求：

- 使用 ease-out 或平滑弹性曲线
- 不使用夸张弹跳
- 不使用长时间粒子动画
- 尊重 `prefers-reduced-motion`
- 动效完成后界面应恢复稳定

---

## 13. 状态设计

至少实现以下状态：

### 首页

- 默认
- Omnibox 聚焦
- 模式切换
- 输入中

### 记忆搜索

- 加载中
- 有结果
- 无结果
- 错误
- 键盘高亮
- 结果打开

### AI

- 准备中
- 正在检索
- 正在构建上下文
- 等待模型
- 正在生成
- 成功
- 被截断
- 失败
- 证据不足
- 审计信息可用

### 侧栏

- 隐藏
- hover 预触发
- overlay 展开
- push 展开
- 手动锁定
- 自动收回

## 14. 无障碍与键盘

必须满足：

- 所有核心功能可使用键盘完成
- 焦点状态清晰
- 模式切换有可读标签
- 图标按钮有 `aria-label`
- 文本与背景对比度合理
- 结果列表可通过方向键导航
- 支持 `prefers-reduced-motion`
- 不依赖颜色单独传达状态
- 不因浏览器缩放 125% 或 150% 破坏布局

## 15. 工程边界

### 15.1 前端不得擅自改动

- 主生产数据库
- Profile 数据库
- Semantic 数据库
- Runtime 数据库
- v8.0 Reviewed Binding 规则
- v8.0 Runtime Ledger 结构
- 生产凭据读取逻辑
- 现有检索与 Context Assembly 语义

### 15.2 不新增依赖原则

v8.1 不应为了 UI 重构引入：

- 本地大模型
- 远程意图分类 API
- 新的 Agent 框架
- 重型前端状态管理框架，除非现有工程明确需要
- 大型动画引擎，除非普通 CSS 无法完成

### 15.3 兼容原则

- 保留现有后端 API
- 尽量以适配层连接旧接口
- 不因视觉重构破坏 v8.0 生产闭环
